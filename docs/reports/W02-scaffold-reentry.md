## Commands actually run

The following is the runnable reproduction used from the repository root. The
observed temporary directory was `/tmp/kb-w02-reentry.8FVoUT`; it was deleted at
the end. `$repo` points only to this checkout, and `$target` contains synthetic

```bash
set -euo pipefail
repo=$PWD
work=$(mktemp -d /tmp/kb-w02-reentry.XXXXXX)
target="$work/synthetic-consumer"

PYTHONPATH="$repo" python -m kb_bootstrap.cli \
  --target "$target" --type single >"$work/first.stdout"
(
  cd "$target"

  >> "$target/.agents/skills/kb-lookup/SKILL.md"

  --target "$target" --type single >"$work/repeat.stdout"

  cd "$target"
```

## Code-path characterization

The initializer currently:

- copies the three always-available single-file skills with `shutil.copy2`;
- copies the `market-research` tree with `dirs_exist_ok=True`;
- opens `qmd.json`, `qmd/collections/wiki.yaml`, and
  `qmd/collections/raw.yaml` with mode `w`;
- preserves an already marked `.gitignore`, touches existing `.gitkeep` files,
  and conditionally preserves the three lesson data/routing files; and
- overwrites the optional `kb-capture` skill when that option is selected.

This is a characterization, not an exhaustive safety test. It did not exercise
`umbrella`, `--with-project-lessons`, partial trees, type changes, symlinks,
non-regular files, permission or injected I/O failures, concurrency, different
filesystems, or template-version drift. It used no QMD executable, model,
networked consumer, credentials, or real consumer data. Passing hashes establish
only the bytes observed in this one synthetic run; they do not establish an
accepted update contract or filesystem transactionality.

## Related bounded precedents

Accepted ADR-002 treats complete existing project-lesson state as a preserving
no-op and blocks on partial/conflicting state; it plans and stages its bounded
installation before exclusive publication and promises only ownership-aware
compensating rollback. Accepted ADR-004 bounds a managed-block replacement,
rejects escaping/symlinked/non-regular paths, checks source identity and bytes
before publication, and documents the remaining post-check race. Those patterns
support the separate Proposed decision in
`docs/proposals/W02-scaffold-update.md`; they do not automatically extend either
accepted decision to whole-scaffold re-entry.
