# kb-bootstrap canonical OKF v0.2 profile

This document defines the deterministic profile used by generated canonical wiki guidance and `kb-bootstrap validate`. It targets Open Knowledge Format (OKF) v0.2 while keeping stricter repository graph integrity separate.

Official public specification:

- https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/main/SPEC.md

## Scope

The profile applies to ordinary canonical Markdown concept files below the selected `--dir` root.

It excludes:

- any directory named `raw`, case-insensitively;
- any directory named `lessons`, case-insensitively, whose files use a separate lesson schema;
- reserved `index.md` and `log.md` files, case-insensitively, at every directory level.

Static symlinked canonical roots, concept files, and non-excluded directories fail closed with sanitized relative diagnostics; the validator rechecks immediately before reading and does not intentionally follow them. Validation assumes a stable checkout and does not claim a race-free filesystem snapshot during concurrent replacement.

## Required concept structure

Each ordinary concept is UTF-8 Markdown and starts with exact YAML frontmatter delimiters:

```markdown
---
type: Concept
---

# Example
```

`type` is the only always-required OKF v0.2 key. It must be a non-empty string. There is no fixed type registry; unknown type values are accepted.

## Generated defaults

`kb-wiki-builder` recommends:

```yaml
type: Concept
title: Example title
description: One-sentence summary.
tags: [example]
status: stable
```

Validation rules for fields generated by this profile:

| Field | Rule |
|---|---|
| `type` | Required non-empty string |
| `title` | Optional; when present, a string rather than explicit `null` |
| `description` | Optional; when present, a string rather than explicit `null` |
| `tags` | Optional; when present, a list of strings rather than explicit `null` |
| `status` | Optional; when present, `draft`, `stable`, or `deprecated` rather than explicit `null`; OKF interprets absence as `stable`, but the validator does not insert or synthesize the field |

Producer-defined fields and unknown types are accepted. Frontmatter scalar values are interpreted as authored strings for this profile instead of allowing YAML 1.1 boolean/date/number coercion to change type checks. Validation leaves the original source bytes unchanged; it never rewrites, normalizes, drops, or reorders frontmatter and does not claim a metadata round trip.

## Deferred optional families

OKF v0.2 also defines optional provenance, trust, lifecycle, and computation fields such as `sources`, `generated`, `verified`, `stale_after`, and Attested Computation fields. They are accepted as additional metadata but are not semantically validated by this minimal profile.

The [bounded canonical provenance/freshness profile](CANONICAL_PROVENANCE_FRESHNESS_PROFILE.md) validates `generated`, `verified`, `sources`, `status`, and `stale_after` as a separate report section. Other optional trust/computation semantics remain outside this minimal profile.

## Reserved files

`index.md` and `log.md` are not ordinary concepts and are excluded from concept-frontmatter validation. This increment does not enforce their optional/conventional body structure and does not rewrite version declarations.

## kb-bootstrap graph integrity extension

OKF v0.2 consumers must tolerate broken cross-links. `kb-bootstrap` intentionally retains a stricter, separately labelled repository-integrity check:

- dead links fail;
- orphan concepts are warnings;
- `raw/` directories are excluded.

A dead-link failure therefore means the repository did not pass the kb-bootstrap graph-integrity extension. It does not mean the Markdown file is non-conformant with core OKF v0.2.

## Validation

```bash
kb-bootstrap validate --dir kb --project-root .
```

The command reports three independent read-only checks:

1. canonical OKF v0.2 profile;
2. kb-bootstrap graph integrity;
3. QMD collection declarations.

The overall command returns failure when any local required check fails. It never migrates, repairs, or rewrites canonical files.

## Valid fixture

```markdown
---
type: Architecture
title: Service boundaries
description: Documents the stable component ownership boundaries.
tags: [architecture, ownership]
status: stable
owner_team: platform
---

# Service boundaries
```

`owner_team` is an unknown extension and is accepted unchanged.

## Invalid fixtures

Missing required type:

```markdown
---
title: Missing type
---
```

Invalid generated lifecycle value:

```markdown
---
type: Concept
status: active
---
```

Both fail deterministically. The validator reports the file and category without printing document contents or rewriting it.

## Non-actions

This profile does not:

- migrate or repair existing content;
- enforce a fixed type taxonomy;
- validate project/shared lesson files as canonical concepts;
- semantically validate deferred provenance/freshness/computation families;
- change QMD indexes or collections;
- write to consumer repositories or external stores.
