# ADR-016: Block conflicting scaffold repeat without upgrading templates

**Status**: Accepted
**Date**: 2026-10-03
**Authors**: Pi coding agent
**Supersedes**: None
**Related**: Issue #123, #121; ADR-002, ADR-004

## Context

Synthetic W02 reproduction observed ordinary initialization overwriting consumer-edited QMD configuration and installed skills. The owner accepted the first safe-repeat increment of W02 and confirmed recording it as ADR-016. This is a faithful record of that approval, not acceptance of the proposal's future template updater or adoption workflow. Existing read-only diagnostic is not an operational guard; its Windows descriptor limitations do not establish safe initialization.

## Decision

Before any ordinary initialization mutation, build a complete in-memory map of the three generated QMD outputs and all ordinary installed skill files from trusted package inventory, excluding existing cache artifacts. Do not discover managed files by walking the consumer tree. Reject incomplete/unreadable package inventory; do not hardcode the current inventory count.

Classify only mapped destinations beneath the explicit target: matching exact generated bytes, content-differs, missing, unsafe type/path, or unavailable. Reject escaping/absolute managed names, symlink components and nonregular destinations; inability to establish a required classification blocks. Report sorted relative paths/categories without contents or private absolute paths.

A complete matching scaffold with delegated valid no-op state succeeds with zero writes, directory creation or staging. Any mixture of matching/missing, differing/unsafe/unavailable destination, or delegated conflict blocks the entire ordinary repeat before mutation; no gap filling, force switch, normalization or auto-merge. All mapped paths absent may use the first-initialization creation path only if every delegated contract is eligible; unrelated pre-existing files do not make them managed data.

Delegate optional lesson/routing state to ADR-002: complete valid populated lessons are preserved, partial/invalid state blocks, all-absent state uses its exclusive enablement. Preserve ADR-004 managed AGENTS boundaries and existing additive gitignore semantics; directories/empty markers remain additive/idempotent. Use non-mutating state inspection for delegated contracts before any fixed-map mutation; never call an all-absent mutating installer to obtain its classification. On an ordinary repeat, requested all-absent lesson state is a pending creation action, not delegated no-op: block that repeat and direct the owner to the existing explicit enable-project-lessons command. First initialization may invoke that installer only after all preflight passes. Existing init does not create a managed AGENTS block, so this guard must not begin doing so. Preserve unrelated KB articles, AGENTS content, custom skills and consumer-added files inside packaged skill directories; never classify them as extra conflicts or remove them.

This first increment adds no version registry, persisted baseline, template upgrade/adoption, generic updater or public preview command. It provides no multi-file atomicity or hostile-writer guarantee; use stable locally controlled targets. First-initialization publication hardening is separately reviewable and must disclose owned partial state on failure, never delete foreign data.

## Alternatives Considered

- Unconditional overwrite: rejected because consumer-owned edits are destroyed.
- Treat all extra paths as conflicts: rejected because unrelated consumer files are not managed state.
- Whole-file template equality for lessons/AGENTS/gitignore: rejected because accepted specialized contracts allow valid edits.
- Skip every existing file: rejected because partial/incompatible scaffolds would be reported successful.
- Broad force or automatic merge: rejected because it expands destructive authority.
- Wait for updater metadata: rejected because safe repeat needs no historical registry.
- Global transactionality: rejected because local filesystem operations cannot make that promise.

## Consequences

### What gets easier

- Identical ordinary repeats are harmless; conflicting managed edits are preserved and actionable.

### What gets harder

- Closed inventory and delegated read-only classification must precede all writes; a package revision change may block repeat and needs a separately approved update path.

### What does not change

- Consumer ownership, lesson IDs/routing, managed AGENTS semantics and local/private runtime data remain authoritative; no updater, migration or model acquisition is authorized.

## Rollback

Revert guard integration; warn that old repeat behaviour can overwrite files again. Do not restore/delete consumer content automatically. A no-op or blocked repeat needs no data rollback. Future template updates require separate approval.
